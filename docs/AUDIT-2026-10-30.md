# University portal backend and source audit

**Date:** 2026-10-30  
**Repository checked:** `Mansi-Kumawat/aptohire-university` (`main`)  
**Scope:** source alignment to the shared AptoHire backend contract and project acceptance criteria; workspace-only source changes.

## Result

The existing portal had several backend-connection gaps. The workspace source was updated to align the University adapter with the backend contract, schema grants, and RLS rules. The existing UI theme/design was preserved.

### Changes made

- Added the shared backend `CONTRACT.md`, `FROZEN-CONTRACTS.md`, and relevant schemas to `docs/`; linked them from the README and removed stale plan text.
- Read University membership through the member-scoped `my_university_v` view.
- Read student names and derived data from `university_students_v`. For roster emails, the adapter now separately selects only columns granted to authenticated members; it does not request protected `full_name`, `program`, or identity-link columns directly from `roster_entries`.
- Added stable, scoped 1,000-row pagination for both the authorized student projection and roster data.
- Corrected roster deletion: first checks the authorized projection for an unclaimed entry, then requests deletion by roster ID and University ID. It does not filter directly on the deliberately ungranted `roster_entries.student_id`; the database delete policy remains the authoritative unclaimed-only guard.
- Aligned University placement changes to unclaimed roster entries via `roster_entry_id`, using guarded update/insert rather than an invalid upsert. Claimed student outcomes remain student-managed in the UI.
- Tightened local roster/import report validation and added adapter/mock coverage for column grants, deletion, placement writes, and unclaimed roster outcomes.
